Das Herzstück lief nicht. Es war an 5 Stellen gebrochen.

Nach dem Voice-Gespräch sollte eine Multi-Agent-Analyse als Report mit PDF herauskommen. Es kam: nichts. Die Spurensuche durch eine Kette, in der jeder einzelne Baustein funktionierte — und trotzdem nichts ankam.

Lesezeit ~5 Min · Stack: Next.js · FastAPI · Supabase · ElevenLabs · WeasyPrint · Python 3.11

TL;DR

Symptom: „Das Herzstück unserer App funktioniert nicht." Gespräch beendet → keine Analyse, keine Animation, kein Report.

Befund: Die Pipeline selbst war gesund. Aber fünf unabhängige Brüche entlang der Kette verhinderten, dass sie je startete oder ihr Ergebnis ablieferte.

Methode: An jeder Systemgrenze nachsehen, was wirklich passiert — statt zu raten. Jeder Bruch hatte eine andere Ursache in einer anderen Schicht.

01Eine Kette, fünf Brüche

Der Ablauf klingt simpel: Hotel spricht mit der KI-Stimme „Ada" → 9 Agenten analysieren → fertiger Beratungs-Report mit PDF/PPTX/Excel. Genau diese Kette war an fünf Stellen unterbrochen — jede in einer anderen Schicht des Stacks:

  1. Frontend · Der Übergang feuerte nieDie Voice-Seite lauschte auf Events convai-call-start/-end, die das ElevenLabs-Widget gar nicht sendet. Das echte Event heißt elevenlabs-convai:call. Folge: Beim Auflegen wurde die Analyse nie gestartet. Beweis: 0 Pipeline-Läufe seit Wochen.
  2. Pipeline · gesundDie 9 Agenten liefen sauber durch und produzierten echte, spezifische Beratung aus den hochgeladenen Zahlen. Dieser Teil war nie das Problem — wichtig zu wissen, bevor man „das Backend" verdächtigt.
  3. PDF · Sprach-Version stolperteDer PDF-Generator hatte einen Backslash im f-String-Ausdruck — auf dem Server (Python 3.11) ein harter SyntaxError. Erzeugung crashte beim Import.
  4. Container · fehlende Systembibliothekencannot load library 'libgobject-2.0-0' — die PDF-Engine WeasyPrint braucht Pango/Cairo/GLib, die im schlanken Container nicht installiert waren.
  5. Storage · Upload lautlos blockiertDie fertigen Dateien wurden erzeugt, aber der Upload scheiterte still an einer Berechtigungs-Regel (RLS-403) — der Hintergrund-Job war nicht als Nutzer authentifiziert. Der Download-Bucket blieb immer leer.

02Warum „das Backend ist kaputt" der falsche Reflex war

Vier von fünf Brüchen lagen nicht dort, wo man zuerst sucht. Der erste war im Frontend (ein Event-Name). Zwei waren Infrastruktur (Python-Version, fehlende OS-Bibliotheken). Einer war eine Datenbank-Policy. Nur die Pipeline „in der Mitte" — der naheliegende Verdächtige — war kerngesund.

Die Wurzel hinter den Wurzeln

Ein End-to-End-Flow ist nur so stark wie seine schwächste Übergabe. Die Bugs saßen nicht in den Komponenten — sie saßen zwischen ihnen: Frontend↔Widget, Code↔Python-Version, App↔Container-OS, Backend↔Storage-RLS.

03Wie ich es gefunden habe

Kein Raten — an jeder Grenze den echten Zustand messen: das tatsächlich gesendete Widget-Event aus dem Bundle gelesen; die echte ElevenLabs-Conversation inspiziert; die Pipeline live Schritt für Schritt gepollt; die Container-Logs nach dem stillen Fehler durchsucht; den Upload isoliert im Container getestet. Jeder Schritt lieferte genau einen nächsten Bruch — bis die Kette stand.

04Das Ergebnis

Ein echter Lauf, vollständig belegt: Gespräch → 9 Agenten → 16-seitiger Beratungs-Report → report.pdf (73 KB) · report.pptx (49 KB) · report.xlsx (28 KB) im Bucket, herunterladbar. Dazu neu: ein Dashboard als Analyse-Einstieg und ein Operations-Board, das die generierten Use-Cases von Backlog → In Arbeit → Erledigt verfolgbar macht.

05Was ich mitnehme

  • „Es funktioniert nicht" ist eine Kette, kein Punkt. Erst die Grenzen kartieren, dann an jeder messen.
  • Der gesunde Teil lenkt ab. Die Pipeline lief — genau deshalb fühlte sich „das Backend" falsch an. War es auch.
  • Stille Fehler sind die teuersten. RLS-403 und ein leerer Bucket schreien nicht — man muss an der Grenze nachsehen.
  • Infrastruktur ist Code. Eine Python-Minor-Version und eine fehlende OS-Bibliothek kippen ein perfektes Feature.

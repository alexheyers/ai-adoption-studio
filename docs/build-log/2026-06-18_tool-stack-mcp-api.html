Der Tool-Stack des Studios — und die eine Regel, wann MCP und wann API

Voice, LLM, Recherche, Automatisierung, Daten, Deliverables: sieben Funktionen, je ein empfohlenes Werkzeug. Warum jedes nötig ist — und über welche Leitung es andockt.

Recherche-Stand 2025–2026 · MCP-Spec 2025-11-25 (Streamable HTTP + OAuth 2.1) · Stack: Next.js · FastAPI · Supabase · Hostinger-VPS

Leitprinzip

„API als Fundament, MCP als Agent-Fassade.“

Jeder Dienst behält seine REST-API/SDK als belastbare, deterministische Laufzeit-Anbindung — FastAPI ruft direkt. MCP nur dort, wo (a) ich beim Bauen mit Claude Code Werkzeuge dynamisch entdecke, oder (b) ein Agent zur Laufzeit eine Fähigkeit als Tool entdecken/auswählen soll.

Faustregel: REST/SDK im Daten- und Control-Pfad (reproduzierbar, schnell, retrybar, Budget-Caps). MCP für Agent-Tooling und Build-Zeit.

01Executive Summary

Das Studio hat sieben Funktionen, von der Dokument-Annahme bis zum fertigen Deliverable. Für jede gibt es eine Ein-Satz-Empfehlung:

  • (1) Onboarding / Upload — Supabase Storage + RLS, Pfad org_id/run_id (REST/SDK).
  • (2) Vorab-Recherche — Tavily + Exa (zwei Such-Achsen) + Google Places (Geo/Wettbewerb) + Destatis/DEHOGA (DACH-Fakten) + Firecrawl (Volltext). Runtime via REST in n8n, explorativ via MCP.
  • (3) Voice-Ada — bei ElevenLabs Agents bleiben (beste Deutsch-Qualität). Kontext per Dynamic Variables / Overrides vor dem Call, Transkript per Post-Call-Webhook danach.
  • (4) Transkript-Auswertung — ElevenLabs-Webhook → n8n → Supabase.
  • (5) Multi-Agenten-Endanalyse — Claude Opus 4.8 + Claude Agent SDK (Per-Run-Isolation der 9 Agenten), deterministisch von FastAPI getaktet.
  • (6) Deliverables — Presenton (Pitch-Decks, self-hosted) + Carbone (Excel/Report/Rechnung) + WeasyPrint (Print-PDF).
  • (7) Automatisierung — n8n bleibt Glue + MCP-Hub, ABER die fragile langlaufende LLM-Kette zieht in eine Durable-Execution-Schicht (Inngest, self-hosted).
Die einzige echte Architektur-Änderung

NICHT n8n die robuste, langlaufende Per-Run-Pipeline orchestrieren lassen — der 300s-Cap, Memory-Pressure und hängende LLM-Calls killen sonst den ganzen Run. Stattdessen Inngest als durablen Motor einziehen; n8n bleibt der sichtbare Glue / MCP-Hub. Gleichzeitig ein starkes Bewerbungs-Narrativ: „Ich trenne Orchestrierung von Glue.“

03MCP-Verbindungen

MCP wird selektiv eingesetzt — fast immer zur Build-Zeit mit Claude Code oder für agentische Tool-Discovery zur Laufzeit. Nie als Inferenz- oder Massendaten-Kanal.

  • Supabase MCP (offiziell, read_only=true + project_ref)Schema inspizieren, Migrationen, Edge Functions, Logs/Advisors debuggen — ohne SQL-Copy-Paste. NUR Dev-Zeit gegen Staging (dokumentierter Prompt-Injection-Leak).Claude Code (Mac) ↔ Supabase · NIEMALS im Laufzeit-Pfad
  • n8n MCP Server TriggerStudio-Workflows (starte_recherche, erzeuge_deliverable) als Tools für Claude/Ada exponieren — sichtbares Build-in-Public-Orchestrieren echter Workflows.Claude/Agent ↔ n8n-Workflows · Bearer/OAuth-Pflicht
  • n8n MCP Client Tooln8n-AI-Agent zieht externe MCP-Server (Supabase/Notion/Tavily) als Tools — Klammer zwischen Build-Zeit-Claude und Produktion.n8n-Agent ↔ externe MCP-Server
  • n8n native Instance-MCP (Public Preview)Neue Glue-Workflows direkt aus Claude Code generieren statt manuell klicken — reine Build-Velocity bei kurzem Runway.Claude Code ↔ n8n-Instanz · reines DEV-Tool
  • ElevenLabs MCP (offiziell)Adas Agent-Konfiguration, Tools, Knowledge-Base per Claude verwalten (Agent CRUD, TTS, Transcription) — Build-Zeit-Pflege.Claude Code ↔ ElevenLabs · Runtime dockt Ada via Server-Tools/Webhook, nicht hierüber
  • Notion MCP (offiziell v2.x, API 2025-09-03)Onboarding/PM/Decision-Log direkt in Notion (Business-SSoT) schreiben/lesen.Claude Code ↔ Notion · Runtime alternativ via n8n-Notion-Node
  • Linear MCP (offiziell, remote, OAuth)Dev-SSoT pflegen (Team ALE, 5 Phasen-Milestones) — jeder Build-Schritt = Linear-Issue + LinkedIn-Inhalt.Claude Code / Skill /studio ↔ Linear · kein Kunden-Runtime-Dock
  • Presenton MCP (/mcp, Bearer)Der Claude-Analyse-Agent erzeugt das Pitch-Deck autonom als Tool-Call, wenn er selbst entscheidet WAS er rendert.Analyse-Agent ↔ Presenton (VPS) · alternativ deterministisch via REST
  • Carbone MCP (render_document)Agent rendert Excel/Report/Rechnung selbst aus Analyse-JSON, wenn agentisch entschieden.Claude-Agent ↔ Carbone (self-hosted) · alternativ via n8n-Node
  • Such-/Geo-MCP (Tavily / Exa / Google-Maps / Brave / SerpAPI)Explorative Nachrecherche zur Build-Zeit oder wenn ein Agent bei Lücken selbst nachsucht.Agent ↔ Recherche-Dienste · Runtime-Pflichtabfragen via REST in n8n

06Risiken

  • Hängende LLM-Calls in n8n. 300s-Cap + Memory-Pressure; ein hängender 90s-Claude-Call kann den ganzen Run killen. Mitigation: Durable-Execution-Schicht (Inngest, step.run/Step Journaling); n8n nur als Glue/Hub.
  • Supabase-MCP Prompt-Injection („lethal trifecta“). Dokumentierter Leak kann Mandantendaten exfiltrieren. ZWINGEND read_only + project_ref, nur gegen Staging, NIE Live-Runtime. Laufzeit-Zugriff ausschließlich via RPC/REST mit erzwungenem org_id-Filter.
  • DSGVO / Datenresidenz Hospitality DACH. LlamaParse + OpenAI-Embeddings + ElevenLabs schicken Daten in US-Clouds. Sensible Gastdaten/Verträge brauchen self-hosted Docling + lokales Embedding-Modell + EU-Region. Klare Routing-Regel pro Dokumenttyp (Schwelle festlegen).
  • Anbieter-/Preis-Risiken. Tavily-Übernahme durch Nebius (02/2026) — API/Preis beobachten, Brave/SerpAPI real parallel verdrahten. Brave Free-Tier fällt 12.02.2026 weg. Google-Places-SKU-Modell seit 03/2025 geändert (kein $200-Pool).
  • Kosten-Akkumulation pro Run. Places ($17/1k Details) + Tavily + Exa + Firecrawl + LlamaParse + Claude-Token summieren sich. Hartes Kosten-Cap pro Run (Places nur Nearby; Branchenzahlen cachen; Prompt Caching; Extraktion auf Haiku/Sonnet, nur Synthese auf Opus).
  • VPS-Kapazität (srv1405308). pgvector-HNSW-RAM + Docling-VLM + Presenton + Carbone + Playwright-Chromium + n8n + Inngest + FastAPI parallel. RAM/Container-Budget prüfen; Engines lazy starten oder Supabase Cloud (EU) für Vektor-Store, ggf. Restate statt Inngest (2vCPU/4GB).
  • Ada-Briefing-Zuverlässigkeit. Briefing IMMER serverseitig (n8n) verdichten + schema-validieren bevor es an ElevenLabs geht — nie rohe Suchtreffer durchreichen (Token-Overflow + Halluzination). Token-Limit pro EL-Agent verifizieren; ab Schwelle auf per-Run-Knowledge-Base+RAG. system__-Variablen sind NICHT überschreibbar.
  • RAG-Latenz im Live-Call. pgvector-Lookup während des Voice-Interviews muss <300ms sein — RPC/Index-Tuning vorab benchmarken, sonst stockt Ada.
  • Inngest self-host. INNGEST_SIGNING_KEY + INNGEST_EVENT_KEY zwingend (sonst Crash-Loop) — in reference_credentials.md aufnehmen. Migrationspfad zu Temporal für SaaS-Horizont-2 als ADR dokumentieren (kein Lock-in).
  • MCP-Sicherheit allgemein. Endor-Labs fand 82% der MCP-Implementierungen Path-Traversal-anfällig. Least privilege strikt; exponierter n8n-MCP-Trigger braucht Bearer/OAuth-2.1; remote MCP = OAuth-2.1-Resource-Server + RFC-8707.
  • Beta-Reife mehrerer Bausteine. Anthropic Managed Agents (pptx/xlsx-Skills), n8n-Instance-MCP, Google-Maps-Remote-MCP, Restate — für Pitch-Deadline 21.07. evtl. zu früh. Fallback: Gamma-API als 1-Tag-Deck-Notnagel, Presenton als H2-Ausbau.
  • Deliverable-Vertrag fehlt. Ohne EIN verbindliches JSON-Schema zwischen Endanalyse und Generierung rendern Presenton und Carbone aus unterschiedlichen Quellen. Single-Source-Schema definieren.
  • Offene Architektur-Entscheidungen. 9-Agenten-Schnitt (bestimmt Modell-Mix); linear vs. zyklische Refinement-Loops (Agent SDK vs. LangGraph/Pydantic-AI+Temporal); Web-Interview vs. Telefonie/SIP (verschiebt Voice-Wahl Richtung Vapi/Retell/LiveKit); AT/CH-Branchenquellen oder nur DE als Showcase-Tiefe.
